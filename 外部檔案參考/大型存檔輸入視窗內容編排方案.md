## 1. 設計方向

將輸入視窗改成「依設定工作分類的專案工作區」，主要順序為：

**車站與軌道 → 車型與服務 → 停站模式 → 班表與接續 → 模擬設定。**

基準存檔包含 28 站、60 個月台、65 條軌道區段、3 種服務、6 種停站模式及 8 筆手動班表。這個規模需要清單、篩選與關聯編輯，不能把所有欄位攤在同一張表裡。

重新編排只調整輸入入口與資訊呈現；底層仍保存同一份 Schema 8 資料，不建立第二套營運資料源，不改變 topology-native runtime 的物理權威。

## 2. 目前混亂的主要原因

1. 「基礎設施」有 13 個分頁，車站、軌道、營運作業和底層接續資料混在同一層。
2. 設定一座折返站，需要跨越月台、設施、折返作業與車站作業。
3. 車型和模擬設定都有速度、煞車、車長等欄位，使用者難以判斷修改哪裡才影響該班列車。
4. 表格依資料屬性自動產生欄位，許多參照仍以編號文字呈現，操作容易變成「編 JSON」。

## 3. 左側導覽與頁面分工

```text
專案總覽

路線建置
  車站與月台
  軌道與設施

營運規劃
  車型
  服務與行車路徑
  停站模式
  班表與接續

模擬設定

進階資料 ▸
```

- 「快速建立」移到新增專案流程；載入大型存檔後直接進入專案總覽。
- 「分析結果」留在主視窗。
- 驗證摘要整合到工作區底部，完整問題清單可展開。
- 導覽順序提供建議流程，不強迫既有專案使用者逐頁操作。

| 頁面 | 主要輸入內容 | 對應 JSON |
|---|---|---|
| 專案總覽 | 名稱、路線摘要、設定完整度、待修正問題 | `projectName`、各資料集合摘要 |
| 車站與月台 | 站名、預設停站時間、月台、停車位置、本站營運作業 | `topology.stations`、`topology.platforms`、`topology.stationOperations` |
| 軌道與設施 | 區段長度、方向、速限、折返／待避設施；進階展開坡度與曲線 | `topology.edges`、`topology.turnbackFacilities`、`topology.passingFacilities`、`topology.speedLimits`、`topology.gradients`、`topology.curves` |
| 車型 | 車長、最高速度、加速度、煞車、Jerk、牽引與惰行 | `vehicleTypes` |
| 服務與行車路徑 | 服務分類、顏色、預設車型與停站模式；上下行路徑及候選月台 | `serviceTypes`、`serviceRoutes`、`directionRouteBindings` |
| 停站模式 | 各站停靠／通過／折返、停站秒數、通過速限、指定待避 | `stopPatterns.instructions` |
| 班表與接續 | 發車方式、時間、方向、服務、車型、停站模式、接續車次 | `dispatch` |
| 模擬設定 | 起始時鐘、營運控制模式、進站控制、安全參數、預設播放倍率 | `simulation`、`operations`；基準與預設值另見第 7 節 |

## 4. 車站與月台：路線編輯的主要入口

使用者通常比較容易從「我要改 O20 站」開始，而不是先判斷該修改哪一張資料表。

採用「左側車站清單＋右側本站內容」：

```text
車站搜尋／篩選             O20 車站
─────────────────────────────────────────
O01                       基本資料
O02                       月台配置
…                         折返與待避
O20 〔折返〕              本站配線預覽
…
```

選到 O20 時，能在同頁處理：

- **基本資料：**站名、預設停站秒數。
- **月台配置：**月台名稱、方向、有效長度、停車位置、允許車型／服務。
- **折返與待避：**使用哪座設施、到達與出發月台、到達與出發路徑、最短折返時間。
- **配線預覽：**反白目前月台及設施，選取後能跳至軌道詳細設定。

「設施怎麼建」由軌道與設施頁負責；「本站如何使用設施」集中在車站頁。本站作業入口整合 `stationOperations`、`turnbackOperations` 與 `passingOperations` 的關聯，但仍編輯原本同一筆資料，不產生第二套設定。

## 5. 停站模式：改成比較矩陣

大型存檔的 6 種模式包含全停、區間、快速，以及不同待避安排。逐一開啟模式很難看出差異。

### 5.1 顯示與編輯方式

- 橫列為車站，直欄為停站模式。
- 儲存格顯示「停靠 30 秒」「通過」「折返」「停靠＋待避」。上述為 UI 組合顯示，不新增存檔動作列舉。
- 點選儲存格後，在詳細區編輯秒數、通過速限與待避目標。
- 提供「複製模式」「批次設為停靠／通過」「只顯示差異站」。
- 不屬於適用路徑的車站顯示「不適用」，避免被誤設為通過。
- 適用路徑與候選車站須由現有路徑及參照資料確認，不從畫面排序或站號猜測。

### 5.2 指定待避

目前 JSON 的指定待避應直接顯示在矩陣中，例如：

| 停站模式 | 車站 | 指定等待的車次 |
|---|---|---|
| 全程車全停（O04 待避） | O04 | `EXPRESS-DOWN-01` |
| 全程車全停（O04 待避區間車） | O04 | `SECTION-DOWN-01` |
| 全程車全停（O13 待避） | O13 | `EXPRESS-DOWN-01` |

介面以可辨識的車次名稱呈現，必要時附編號。待避目標引用班表車次，因此應提示「尚未指定車次」，並允許班表建立後回來選取。

修改共用模式前，列出受影響的班次。班表頁可跳至對應模式的待避設定，但不建立獨立的班次停站資料副本。

## 6. 班表與接續：集中處理實際開車安排

頁面頂部選擇「手動班表／固定班距」及車輛分配方式。

主表只保留常用欄位：

| 發車時間 | 方向 | 服務 | 車型 | 停站模式 | 起點月台 | 終到處理 |
|---|---|---|---|---|---|---|
| 時間輸入 | 上／下行 | 服務選單 | 車型選單 | 模式選單 | 合法候選月台 | 結束／續行摘要 |

選取一班車後，下方展開車輛編號、車次編號、指定接續及相關待避安排。車輛身分與車次身分必須分開呈現。

針對大型存檔，應能清楚看到：

```text
快速車下行 → O20 折返 → 指定快速車上行
區間車下行 → O20 折返 → 指定區間車上行
```

預覽根據既有路徑、折返作業與接續資料組合顯示，並提供缺漏提示，不自行推導另一套營運結果。

班次數由發車計畫展開結果顯示。`simulation.trainCount` 與摘要班距不再放在主要操作區，避免使用者以為改摘要就會改變班表；原存檔值仍須妥善保留。固定班距模式的有效輸入仍由 `dispatch.simpleHeadwayPlans` 管理。

## 7. 重複與低頻欄位的安排

| 欄位類型 | 建議呈現方式 |
|---|---|
| 每班列車使用的性能 | 以所選「車型」為主要入口 |
| `train.*`、與車型重疊的全域參數 | 放在「進階：基準與預設值」，標示適用範圍 |
| 停站時間 | 顯示設定值、有效值及來源；空白明確表示沿用預設 |
| 車型／月台／服務／車次參照 | 使用可搜尋選單，顯示名稱與必要編號 |
| 多個允許車型、服務、偏好月台 | 使用多選清單，取代逗號分隔文字 |
| 節點、接軌側、有向接續、衝突資源 | 保留進階編輯入口，也能從相關設施跳轉 |
| 示意位置與股道顯示 | 放在「圖面配置」，與實體長度、連接分開 |
| 專案編號、物件識別碼 | 保留進階入口；改動時檢查參照一致性 |
| Schema 版本 | 唯讀 |

不得直接刪除看似重複的欄位。實作時須逐項確認 Engine 的使用位置與覆蓋規則，介面才能正確說明哪個值生效。未確認前，不自行宣稱全域欄位無效，也不自動以車型值覆寫原存檔。

速度顯示以 km/h 為主，距離使用清楚標示的 m 或 km，時間使用秒或時鐘；儲存時由 UI 邊界轉回 Engine 單位。停站有效值與其他摘要應重用既有解析結果，避免在 UI 複製計算規則。

## 8. 視窗共同操作規則

```text
頂部：專案名稱／未套用變更／搜尋
左側：功能導覽
中央：清單、矩陣或配線
右側：選取項目的詳細編輯，可收合
底部：驗證摘要／套用／取消
```

- 一般欄位直接在頁面編輯，不再連續跳出多個小對話框。
- 錯誤可點擊定位到物件和欄位。
- 切換頁面保留草稿，套用前完整驗證。
- 取消或驗證失敗不得污染主視窗目前的專案。
- 一般模式隱藏低頻技術細節，但保留進階入口，不能因簡化介面造成既有資料無法保存。
- 既有專案的未修改欄位須保留原值，包括 `null`、空集合及選填欄位的語意差異。

## 9. 實作順序

1. **重整導覽與常用輸入：**調整表格欄位、參照選單，先改善找不到設定的問題。
2. **整合車站工作流程：**集中月台及本站折返／待避作業，提供設施跳轉。
3. **加入大型營運編輯方式：**停站模式矩陣、班表接續預覽。
4. **補齊編輯輔助：**有效值來源、修改影響提示及進階資料入口。

上述為實作分期，不表示本次已授權或完成程式修改。

## 10. 驗收標準與邊界

### 10.1 大型存檔資料驗收

- 載入基準存檔，不修改直接套用、儲存、重讀後，資料語意不漂移。
- 能完成「改 O20 折返」「改 O04 待避」「新增並接續一班車」，儲存重讀後仍一致。
- 未啟用的班表資料、選填欄位、參照與進階資料不因切頁或套用而遺失。
- 指定接續保留車輛與車次身分關係，不另外生成重複的目標車次。

### 10.2 技術與操作驗收

- 正式實作依專案規範執行 Release build、完整自動化測試及適用 WPF runner。
- 實際使用原生 WPF 視窗完成主要設定流程，檢查捲動、篩選、鍵盤操作、欄位可見性與錯誤定位。
- 離屏測試不等於原生桌面或 DPI 驗收。
- 物理位置仍以 edge-local cursor、明確 port-side 與 directed connection 為準；示意圖位置不改變實體連接。
- 不因 UI 整理變更 Schema、降低 validator 強度或新增第二套 runtime。
