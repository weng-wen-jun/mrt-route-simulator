# 手冊容量分析範例：檔案與驗證說明

來源為交通部運研所《2019年臺灣鐵道容量手冊》都會篇第6章6.1，PDF第593–615頁。本目錄提供8個案例加4個對照／改善分支，共12份可載入的Schema 8檔案。

**這些是容量分析案例，不是手冊整條路線的實體模擬復原。** 所有檔案使用專案維護範例01的三站雙股島式站場作為可載入的示意載體；容量參考點保存手冊的輸入數值，不會自動改變載體路線、車型或列車運行。S1–S14的14站完整路網、道岔聯鎖及現場線形尚未建模；不要把載體運行時間當作手冊結果。

## 開啟方式

使用本輪建置的捷運軟體，開啟本目錄的 `.mrtsim.json`，再選「理論／容量參考點」頁。例七與例八已啟用同一容量情境瓶頸比較；其它檔案維持局部參考點分析。選「敏感度分析」可掃描主線連續通過比例或折返停靠時間，並選填目標班距。

## 正式來源數值與補充假設

- 例二全域參數在圖6-6明載：聯鎖15秒、反應1秒、PHF0.8、營運餘裕0.3。
- 其餘案例未完整圖列全域參數，統一補充採聯鎖10秒、反應1秒、PHF0.8、營運餘裕0.3。這些值不是從發布答案反算，也不因為相符就視為已證實的手冊原輸入。
- 例一、二、三、四、七、八的列車規格依圖／表輸入。例五、六沒有明列列車規格，補充採本機URCS預設：141m、加減速度各1m/s²、煞車因子0.75、352座、站立264m²、密度6人/m²。
- 例五的1.8km是路線示意距離。實際圖6-23參考點欄位為停車位置至橫渡線30m、橫渡線85m，未擅自填入1,800m。
- 例四除了性能與閉塞改善，圖6-19把停站時間改成40秒，而「承上題」與發布結果支持45秒對照分支。兩份均保留，沒有改程式迎合答案。
- 例七主檔採已選定的手冊坡度方向，07b另存URCS相容模式。其餘差異由全域輸入缺漏或手冊圖文不一致造成的可能性尚不能排除。
- 在上述明列假設下，S14单尾軌若欲h≤150秒，停等須約33.890秒以下；33秒檔示範可行值。手冊「35秒以內」是概略說明，不能在未確認全域值時斷言原手冊程式錯誤。

## 範圍、驗證與重建

本批12檔逐一通過Schema 8驗證、容量設定保存往返、CreateRuntime及10秒示意載體smoke。這僅證明檔案可載入及示意載體可執行，不證明手冊真實路網或實際營運容量。完整數據與來源／假設逐案記錄在 [verification-results.json](verification-results.json)。

敏感度CSV：

- [主線通過比例0–1](06-主線通過比例敏感度.csv)，步長0.1。
- [S14尾軌停等10–120秒](08-尾軌停等敏感度.csv)，步長5秒，含150秒目標判斷。

從repository根目錄重新產生：

```powershell
dotnet run --project .\scripts\HandbookCapacityExamples\HandbookCapacityExamples.csproj -c Release -- .
```

產生器只覆寫本目錄的對應輸出，保留其它專案維護範例。容量公式使用目前Engine來源，不另寫一套計算器。
