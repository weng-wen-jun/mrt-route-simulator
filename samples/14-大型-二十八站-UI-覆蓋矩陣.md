# sample 14 大型 Schema 8 UI 覆蓋矩陣

## 使用範圍

本矩陣以 [`14-大型-二十八站完整營運範例.mrtsim.json`](14-大型-二十八站完整營運範例.mrtsim.json) 為基準，對照目前 Schema 8 編輯器和主視窗程式碼，回答每個 JSON 路徑可以在哪裡設定、是否由系統衍生、是否只是相容資料，以及目前仍缺少什麼入口。

這份文件是程式碼與 sample 的覆蓋盤點，也包含部分離屏 WPF 專項回歸；不代表已完成「空白起稿 → 逐頁輸入 → 套用 → 儲存 → 重讀」的真人桌面點測。矩陣中的「可編輯」表示目前存在對應的編輯器或對話框；「未驗收」表示尚未用空白起稿和 sample 14 做完整流程比對。

證據範圍：

- sample：Schema 8，28 站、36 nodes、65 edges、60 platforms、5 resources、69 directed connections、1 turnback facility、4 passing facilities、1 turnback operation、6 passing operations、5 station operations、8 manual timetable rows。
- 編輯器：`src/MrtRouteSimulator.App/TopologyEditorWindow.cs`、`TopologyEditorViewModels.cs`。
- 主視窗載入與播放：`src/MrtRouteSimulator.App/MainWindow.ProjectFiles.cs`、`MainWindow.Topology.cs`、`MainWindow.V2.cs`。
- 目前由 UI 形成的唯一保存文件仍是 Schema 8；主視窗載入後會先完整驗證，再建立 topology-native runtime。

## 狀態標記

| 標記 | 意義 |
|---|---|
| `UI-可編輯` | 有欄位、DataGrid 或對話框可以設定；仍需流程驗收。 |
| `UI-可新增/刪除` | 有建立或刪除入口，但不一定能修改既有所有欄位。 |
| `衍生/唯讀` | 由拓撲、設施精靈、路徑規則或 runtime 產生；沒有直接 JSON 欄位編輯器。 |
| `相容/不作為權威` | Schema 保留欄位或顯示摘要，執行時由其他資料來源決定。 |
| `缺 UI` | 目前沒有能重現該 JSON 值的編輯入口。 |
| `未驗收` | 本輪尚未完成空白起稿、逐頁操作、存檔、重讀及逐值比對。 |

## 未覆蓋 path 與後續修正順序

目前不能由已存在 UI 完整重現或尚未完成驗收的 path，依阻塞程度排序如下：

1. `topology.turnbackFacilities[]`／`passingFacilities[]` 精靈與編輯對話框：驗證複雜設施的建立預設與可執行 `traversals`，並用 sample 14 逐筆驗收。`facilityTrackEdgeIds` 僅供舊檔相容，不作為新設施的執行設定。
2. `topology.turnbackOperations[]`、`passingOperations[]`、`stationOperations[]`：目前已有表格，但新增按鈕使用簡化預設值；需要確認多筆 operation、ID 關聯、平台集合和 dwell 可由空白起稿重建。
3. `topology.directedConnections[]`：目前已有可編輯表格；仍需定義與 editing service 的重建邊界，並驗證 69 筆 sample 接續在套用、存檔、重讀後不漂移。
4. `topology.curves[]`：目前已有欄位表格；sample 是空集合，仍需驗收非空曲線的 offset／半徑與 runtime 行為。
5. `simulation.trainCount`／`headwaySeconds` 已有編輯入口；仍須測試主視窗摘要與派車計畫在不同模式及數值下的語意一致性。
6. `topology.edges[].conflictResourceIds` 與 `topology.platforms[].allowed*Ids`：編輯模型與回歸測試已通過；仍需實際 DataGrid 逐值流程驗收。
7. 所有已有欄位的桌面驗收：從空白 Schema 8 起稿，逐頁設定 sample 14 的代表值，套用、儲存、重讀，逐 path 比較 `null`、空集合、ID 集合、順序和浮點單位轉換。
