# V3.3.0 完整功能驗證範例

範例檔：`V3.3.0-完整功能驗證範例.mrtsim.json`

這是一份 Schema 7 合成測試資料，用來一次檢查 V3.3 的專案讀取、即時路線圖、雙向派車、停站秒數覆寫、停站／跨站、指定車次接續、端點退出、車型性能、移動閉塞、速度曲線、時刻表、區間統計及五類 URCS 空間參考點。數值不是任何真實路線的設計或安全依據。

`archive/` 只保存歷史 V3.2 範例供比對；現行程式會依內部測試政策拒絕其舊 Schema，不應拿來做 V3.3 驗收。

## 操作方式

1. 啟動 `MRT路線進出站時間模擬器.exe`。
2. 選「檔案 → 讀取存檔」，載入本範例檔。
3. 讀取完成後，首頁路線圖應立即改為五站驗證線，並顯示五個空間參考點；這一步不必先建立模擬。
4. 按動畫頁上方常駐的「建立模擬【V3.3】」。
5. 以 `20×` 播放。要看到指定接續車次，至少播放到模擬時鐘 `06:12:00`；完整檢查可播放到約 `06:40:00`。
6. 逐頁查看進出站時刻表、區間物理、移動閉塞與煞車、V2 區間統計、下行速度曲線及列車運行圖。

## 主要情境與預期結果

| 驗證項目 | 範例設定 | 預期結果 |
|---|---|---|
| 五類空間參考點 | V01 站前折返、V02 中間站、V03 銜接點、V04 中央避車線折返、V05 站後折返 | 讀檔後立即出現在首頁路線圖；容量提示與各類參數可在空間參考點設定中檢查 |
| 中間站方向獨立 | V02 下行停站 42 秒、上行停站 11 秒 | 上下行抵達 V02 後的停站時間不同 |
| 指定反向接續 | `EMU-CIRC-01` 的 `RUN-DOWN-001` 指定接續 `RUN-UP-006` | 同一實體 `VehicleId` 於 V05 折返，在 06:12 以指定上行車次發車，不另生成一列車 |
| 端點退出 | `EMU-EXIT-U01`、`EMU-EXP-D02`、`EMU-EXP-U02`、`EMU-EXIT-D03` 均不續行 | 完成端點停站／清車後產生「退出營運」，車輛從路線圖及安全配對消失 |
| 普通／快速停站模式 | 普通車全停；快速車跨越 V02、V04 | 快速車產生跨站事件，速度曲線不中斷為停站 |
| 雙方向派車 | 06:00 起依手動班表由 V01、V05 兩端發車 | 路線圖、時刻表、運行圖及軌跡同時包含上行與下行 |
| 車型與服務類型 | EMU-6／EMU-8；普通車／快速車 | 車次、速度曲線及結果列保留車型、服務類型與停站模式識別 |
| 方向別里程速限 | 雙向 55 km/h、下行 45 km/h、上行 50 km/h | 實際速度曲線在對應方向與里程受限，提前煞車事件可在軌跡中觀察 |
| 月台、軌道與進路 | 雙向主線、V03 避車線、逐區間進路與資源 | 事件包含月台配置、進路預約／釋放；移動閉塞頁產生安全距離歷程 |
| 結果頁 | V2 寫實引擎事件與軌跡 | 時刻表可見「折返接續／退出營運」；V3.3 區間統計含完整篩選與閉塞受限秒數；上下行速度／運行圖均有資料 |

## 自動驗證涵蓋

`tests/MrtRouteSimulator.Tests` 會直接從本檔讀取 Schema 7，建立 V2 `SimulationWorld` 並播放 2,400 秒，檢查：

- 五站、三組速限、兩種車型／服務／停站模式及五類空間參考點完整存在。
- 上下行發車、快速車跨站、指定接續換向及端點退出事件實際發生。
- 退出車輛不再活動，安全距離歷程、時刻表、完成區間統計及雙向軌跡皆非空。

2026-08-24 的桌面實測另確認：發車計畫會自動開啟「手動班表」並顯示 6 列；播放至約 06:17 後，未續行車已從路線圖與即時狀態消失，只剩接續為 `RUN-UP-006` 的 `EMU-CIRC-01`；時刻表、區間物理、移動閉塞、V3.3 區間統計與運行圖均正常產生。

若修改本範例或引擎，請重新執行：

# V3.4 折返檢核範例

範例檔：`V3.3.0-端點站前與中間站中央避車線折返檢核.mrtsim.json`

這是 Schema 7 的引擎檢核專案，數值為合成測試資料，不是實際路線或安全設計。它用兩個獨立情境驗證 V3.4 的資源生命週期：

| 情境 | 設定 | 預期引擎事件 |
|---|---|---|
| 北端站前折返 | `TB01` 的 `BeforeStationTurnback` 啟用 `alternateBerthing`，站場策略為 `RoundRobin`，兩班上行依序接續至 `TB01:UP-A`、`TB01:UP-B` | 目的月台自進路建立起保留；A/B 都被占用時後車記錄「等待進路」；前車折返發車後才釋放月台，不產生碰撞 |
| 中央避車線區間車 | `TB02V` 是路線中的「中央避車線（虛擬站）」；`POCKET_SHORT_TURN` 將它指定為 `Turnback`，並設定 `SIDING:TB02V` 折返資源 | `EMU-POCKET-01` 在 TB02V 停靠、保留月台與避車線資源、換向後以 `CASE-02-POCKET-OUT` 發車 |

桌面操作時，從「檔案 → 讀取存檔」選擇此檔，再建立模擬。停站模式管理視窗可看到「折返」選項；它只能用於已設定為中央避車線的非端點虛擬站。

本輪依使用者要求只完成引擎與 Schema 7 匯入驗證，尚未對此範例執行 Windows 桌面 UI 實測。

# V3.4 雙島四股快速車越行驗證範例

範例檔：`V3.4.0-雙島四股快速車越行驗證.mrtsim.json`

這是 Schema 7 的合成多站範例，用來檢查受限用地下「站間每方向只有一條正線、僅在雙島四股站內越行」的普通車待避與快速車跨越。數值與站名均非真實路線設計或安全依據。

| 項目 | 設定 |
|---|---|
| 多站路線 | OV01～OV03；只有 OV02 是雙島四股越行站 |
| 站間配置 | `DOWN-MAIN` 是 OV01～OV03 全段唯一的下行正線；快速車只在 OV02 的 1,360～1,600 m 站場範圍轉入通過線 |
| 普通車 | `RUN-LOCAL-001` 先發、全站停靠；抵達 OV02 後轉入 `OV02-D-LOCAL` 待避線。原定停站結束但快速車接近時，會產生等待事件並繼續待避 |
| 快速車 | `RUN-EXPRESS-001` 晚 55 秒發車；具較高優先序與 `canRequestOvertake = true`，跨站 OV02，取得越行資源後轉入 `OV02-D-EXPRESS` 通過線，完成後匯回 `DOWN-MAIN` |
| 自動驗證 | 普通車待避、`OvertakeRequested`、`StationPassed`、`OvertakeCompleted`、普通車後續發車的時序均受測試驗證，且不發生碰撞 |

操作時，從「檔案 → 讀取存檔」載入範例、建立模擬，再以 `20×` 播放。事件列表可依序看到普通車的「等待資源」、快速車的「追越提出／通過／追越完成」，以及普通車在快速車匯回正線後才發車；列車運行圖與下行速度曲線也會顯示同一份 `SimulationWorld` 軌跡。若要以 GUI 編修設施，開啟「路線 → 月台／股道／越行／折返」，在「站內越行」分頁設定普通車待避月台／股道、快速車通過月台／股道、共線正線、分歧公里與衝突資源。

## 重要限制

這是**明確配置的站內越行設施**，不是全線自動排程器：使用者仍須在專案檔設定雙島四股站、待避／通過月台與股道、分歧位置及站前／站內／站後衝突資源。未配置合法設施的共線區段仍只使用移動閉塞，不會憑服務名稱強行讓快速車超車。
